# BeautyBook

Демонстрационный Telegram-бот на Python 3.11+ для записи клиентов в салон
красоты. SQLite является основным хранилищем; синхронизация с Google Sheets
необязательна.

## Требования

- Python 3.11 или новее.
- Токен Telegram-бота и Telegram ID владельца.
- На Windows база `zoneinfo` устанавливается зависимостью `tzdata` из списка
  requirements.
- Для необязательной Google Sheets интеграции — service account Google с
  доступом на редактирование к нужной таблице.

## Установка и запуск в Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и задайте:

- `BOT_TOKEN` — токен, полученный у BotFather;
- `OWNER_ID` — числовой Telegram ID владельца;
- `TIMEZONE` — IANA-имя часового пояса салона, например `Europe/Moscow`.

Затем запустите бота:

```powershell
python main.py
```

Файл `.env` содержит секреты и исключён из Git. Не публикуйте токен и не
храните ключ service account внутри репозитория. `.env.example` содержит
только имена настроек и безопасные демонстрационные значения.

## Расписание и демонстрационные услуги

Начальные часы работы — ежедневно с 09:00 до 18:00 по `TIMEZONE`. Шаг сетки
времени — 30 минут, горизонт записи — 30 дней. Эти параметры изменяются через
`BUSINESS_START_HOUR`, `BUSINESS_END_HOUR`, `SLOT_STEP_MINUTES` и
`BOOKING_DAYS_AHEAD`.

При первом старте в SQLite автоматически добавляются демонстрационные услуги:
стрижка (60 минут), укладка (45 минут) и маникюр (90 минут). Для изменения
начального набора отредактируйте `DEFAULT_SERVICES` в `database.py`. Уже
созданные записи хранят ссылку на услугу; изменения каталога следует проводить
с учётом существующих данных.

Время записи сохраняется в UTC. Бот показывает время клиенту и владельцу в
часовом поясе `TIMEZONE`. Конфликтующие бронирования проверяются внутри
транзакции SQLite `BEGIN IMMEDIATE`.

## Возможности бота

- Клиент выбирает услугу, дату и свободный слот, указывает имя и телефон,
  проверяет данные и подтверждает запись.
- Клиент видит и отменяет только свои будущие подтверждённые записи.
- Владелец получает уведомление о новой записи и может открыть админку командой
  `/admin` или кнопкой главного меню.
- Админка позволяет просматривать записи и расписание на неделю, менять
  статусы, отменять запись и закрывать свободный интервал.
- Клиенту и владельцу отправляются напоминания примерно за час; статусы
  доставки сохраняются, а неотправленные напоминания восстанавливаются после
  перезапуска.
- Ошибка Google Sheets не отменяет локальную запись. Очередь синхронизации
  хранится в SQLite и повторяется фоновым обработчиком.

Команда `/help` описывает клиентские действия, `/cancel` прерывает текущий
сценарий, `/mybookings` показывает будущие записи.

## Google Sheets (необязательно)

1. Создайте Google service account и скачайте JSON-ключ.
2. Храните ключ вне репозитория и предоставьте email service account доступ
   редактора к целевой таблице.
3. Задайте в `.env` оба параметра: `GOOGLE_SHEET_ID` и
   `GOOGLE_CREDENTIALS_FILE`.
4. Перезапустите бота.

Если оба параметра пусты, синхронизация отключена. Идентификатор записи
используется как ключ для обновления строки при повторной синхронизации.
Сведения об ошибках сохраняются в таблице очереди `sheets_sync` SQLite и
попадают в журнал приложения.

## Проверки

Точечные тесты запускаются командой:

```powershell
python -m unittest discover -s tests -v
```

Проверка синтаксиса всех модулей:

```powershell
python -m compileall -q .
```

Перед публикацией проверьте, что `.env`, файл базы и JSON-ключи не добавлены в
репозиторий. Не используйте production-бота и реальные учётные данные в тестах.
